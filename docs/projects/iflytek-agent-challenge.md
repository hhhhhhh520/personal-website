## 评分规则

官方仿真器按四个维度评分：

| 维度 | 分值 | 说明 |
|------|------|------|
| TSR | 60 | 任务成功率（must_satisfy 条件） |
| AS | 20 | 动作合法性（error 扣 5 分 / forbidden 直接 0） |
| ES | 10 | 效率分（步数越少越好） |
| RS | 10 | 鲁棒性（变体通过率） |

## 三阶段架构

核心设计是用**确定性状态机**兜住 LLM 的不确定性，尤其是步数与动作合法性：

1. **Phase 1 — LLM 意图理解（不计步）**：LLM 解析自然语言需求，提取意图与槽位。此阶段不计入步数预算。
2. **Phase 2 — 显式状态机推进（计步）**：把意图交给有限状态机逐步推进工作流，每步产生合法动作。用状态机而非纯 LLM 决策，控制步数、避免 forbidden 动作直接归零。
3. **Phase 3 — 构造最终结果**：汇总执行轨迹，构造满足 must_satisfy 条件的最终输出。

## 工程实践

- **端到端本地验证**：用官方仿真器在本地 train(200)/val(50) 集上复现评分，避免只看单元测试
- **鲁棒性变体测试**：针对 RS 维度构造输入变体，验证 Agent 不因边界输入崩溃
- **LLM 槽位健壮性**：LLM 返回值不裸用 int/float，run() 全程 try/except；槽位前缀污染在确定性入口剥前缀（raw 优先，miss 才剥）
- **迭代提分**：平台得分受约 ±1.7 测量方差影响，多轮架构迭代 + 端点/密钥调整共同推动，最优达 71.47（2026-09-02，阿里云端点首次上平台）

## 设计亮点

1. 认识到「纯 LLM 决策」在计步/合法性约束下的脆弱，改用**显式状态机**接管可控部分
2. 三阶段解耦「理解 / 执行 / 构造」，把不计步的意图理解与计步的执行分离，优化 TSR 与 ES 的平衡
3. 坚持官方仿真器端到端验证 + 变体鲁棒测试，而非依赖单测绿灯
